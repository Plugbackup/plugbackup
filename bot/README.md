# Бот PlugBackup

Telegram-бот для оплаты и выдачи доступа. Единственное место, где клиент регистрируется, платит и получает логин для SFTP. Написан на Python 3.12, aiogram 3 и SQLite.

Что умеет:

- Бета по инвайт-коду (10 ГБ) и платные тарифы в Telegram Stars с автопродлением раз в 30 дней.
- Выдача доступа: проверка SSH-ключа ed25519, выбор ноды с наибольшим запасом, готовая инструкция для restic.
- `/status`, `/upgrade`, `/key`, `/alerts`, `/restore`, `/support`, `/rules`, `/help`.
- Экраны в едином стиле: карточки, цветные кнопки, баннеры, шкала занятого места, один экран на весь диалог (кнопки «Назад» и «Главное меню»).
- Уведомления об окончании подписки, заполнении квоты, блокировке и удалении. Алерты безопасности настраиваются клиентом в `/alerts`.
- Админка `/admin` с ролями: дашборд, клиенты, тарифы, инвайты, рассылки, ноды, техработы, поддержка, заявки на восстановление, платежи с возвратом Stars, админы, журнал, экспорт. Подробнее в разделе «Админка». Ошибки `storectl`, недоступные ноды и сбои платежей приходят в админ-чат.

С нодой бот общается по SSH: вызывает `storectl` (см. [node/](../node)).

## Что понадобится

- VPS с Linux, Python 3.12+, SQLite 3.37+ и клиентом `ssh`.
- WireGuard-туннель до ноды: бот ходит на её адрес в туннеле.
- Нода, настроенная по [node/README.md](../node/README.md).
- Бот в BotFather и его токен. Для платежей в Stars провайдер платежей не нужен.

## Установка на VPS

Команды выполняются от root. Пути можно менять, тогда поправьте юнит.

**1. Пользователь, код, окружение.**

```bash
useradd --system --home-dir /nonexistent --shell /usr/sbin/nologin plugbackup-bot
install -d -m 0750 -o root -g plugbackup-bot /etc/plugbackup-bot
git clone <адрес репозитория> /opt/plugbackup
python3.12 -m venv /opt/plugbackup/bot/.venv
/opt/plugbackup/bot/.venv/bin/pip install /opt/plugbackup/bot
```

**2. Ключ для ноды.** Бот входит на ноду как пользователь `provision`. Ключ без пароля: бот работает без участия человека.

```bash
ssh-keygen -t ed25519 -N '' -C plugbackup-bot -f /etc/plugbackup-bot/provision_ed25519
chown plugbackup-bot:plugbackup-bot /etc/plugbackup-bot/provision_ed25519
chmod 0600 /etc/plugbackup-bot/provision_ed25519
```

Публичную часть (`provision_ed25519.pub`) положите на ноду по [инструкции](../node/README.md), шаг 4.

**3. Отпечаток ноды.** Бот подключается с `StrictHostKeyChecking=yes`, поэтому ключ ноды нужен заранее.

```bash
ssh-keyscan -t ed25519 <адрес ноды в WireGuard> > /etc/plugbackup-bot/known_hosts
ssh-keygen -lf /etc/plugbackup-bot/known_hosts
```

Сверьте отпечаток с тем, что покажет `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` на самой ноде. Без сверки `ssh-keyscan` доверяет первому ответу.

**4. Настройки.**

```bash
install -m 0640 -o root -g plugbackup-bot /opt/plugbackup/bot/.env.example /etc/plugbackup-bot/.env
$EDITOR /etc/plugbackup-bot/.env
```

| Переменная | Что это |
| --- | --- |
| `BOT_TOKEN` | Токен от BotFather |
| `ADMIN_IDS` | Telegram id администраторов через запятую |
| `ADMIN_CHAT_ID` | Куда слать алерты. Бот должен уже получить от этого чата `/start`, иначе писать первым он не может |
| `DB_PATH` | Файл базы, например `/var/lib/plugbackup-bot/bot.db` |
| `PLANS_FILE` | Абсолютный путь к `design/data/plans.json`, например `/opt/plugbackup/design/data/plans.json` |
| `PRICES_STARS` | Цена каждого платного тарифа в Stars за 30 дней, от 1 до 10000 |
| `NODES` | Список нод в JSON: имя, адрес в WireGuard, публичный хост, ёмкость в ГБ, коэффициент перепродажи |
| `SSH_USER`, `SSH_PORT`, `SSH_KEY_PATH`, `SSH_KNOWN_HOSTS_PATH` | Подключение к ноде |
| `STORECTL_TIMEOUT_S` | Сколько ждать ответа `storectl` |
| `DEFAULT_TZ` | Часовой пояс по умолчанию для тихих часов |
| `LOG_LEVEL` | `INFO` или `DEBUG` |

Названия и объёмы тарифов берутся из `design/data/plans.json`, цены в Stars только отсюда. Значения в `.env.example` — заглушки, цены подберите по текущему курсу Stars. Ноды задаются здесь же и применяются при запуске. Нода, убранная из `NODES`, отключается (новые клиенты на неё не идут), но не удаляется.

**5. Проверка и запуск.**

```bash
cd /etc/plugbackup-bot && sudo -u plugbackup-bot /opt/plugbackup/bot/.venv/bin/python -m plugbackup_bot --check
install -m 0644 /opt/plugbackup/bot/deploy/plugbackup-bot.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now plugbackup-bot
journalctl -u plugbackup-bot -f
```

`--check` проверяет настройки, наличие ключа и `known_hosts`, читает тарифы и создаёт базу. Права на файл ключа должны быть `0600`. После старта администратор получает сообщение «Бот запущен».

Юнит написан без проверки на живой системе. Если сервис не стартует, смотрите журнал и ослабляйте строки защиты по одной.

## Профиль бота

Аватар, имя, описания и меню команд ставит скрипт, запускать его надо из папки `bot/` (там лежит `.env`):

```bash
.venv/bin/python scripts/setup_profile.py --dry-run   # показать, ничего не меняя
.venv/bin/python scripts/setup_profile.py             # применить после подтверждения
```

Что делает: ставит аватар JPG 640×640 (`setMyProfilePhoto`), имя, описание и короткое описание на русском и английском, меню команд для клиентов и расширенные меню для владельцев и помощников. Можно выбрать шаги: `--only photo texts commands`. Готовые файлы (аватар и картинка описания) складываются в `profile_out/`.

Картинку описания (640×360, видна в пустом чате до нажатия «Старт») Bot API поставить не умеет, это делается руками в @BotFather: `/mybots` → ваш бот → Edit Bot → Edit Description Picture, затем прислать `profile_out/bot-description.png` как фото, а не как файл. Те же шаги скрипт печатает в конце.

Анимированного логотипа в `design/` нет, поэтому видеоаватар не ставится.

## Эмодзи

Иконки в заголовках и на кнопках берутся из пака [RestrictedEmoji](https://t.me/addemoji/RestrictedEmoji). В коде они называются по смыслу (`E.ok`, `E.lock`, `E.payment`…), какой именно эмодзи за ними стоит, записано в `emoji_map.json`, его можно править руками.

```bash
.venv/bin/python scripts/scan_emoji.py            # сохранить пак в emoji_pack.json и подобрать соответствия
.venv/bin/python scripts/scan_emoji.py --remap    # подобрать заново, затирая правки в emoji_map.json
```

Кастомные эмодзи в тексте и на кнопках (`icon_custom_emoji_id`) Telegram разрешает, только если у владельца бота есть Premium. Если его нет или Telegram по другой причине их отклонил, бот сам переходит на обычные эмодзи, сообщения продолжают доставляться, а в админ-чат один раз приходит пояснение. Чтобы не получать его после каждого перезапуска, поставьте `USE_CUSTOM_EMOJI=false`. Проверить, что видит клиент, можно командой `/emoji_preview` (только администраторам): она показывает пак, соответствия и пробные кнопки.

Баннеры экранов лежат в `design/graphics/png`, путь задаёт `ASSETS_DIR`. Бот загружает картинку один раз и дальше шлёт по `file_id` (кэш в таблице `media_cache`). На сообщения об оплате и готовом доступе ставится эффект конфетти; если Telegram его не примет, сообщение уйдёт без эффекта. Выключить эффекты: `MESSAGE_EFFECTS=false`.

## Админка

`/admin` открывает меню разделов по роли. Роль читается из базы при каждом действии, поэтому снятые права перестают действовать сразу, а у любого обработчика права проверяются на сервере, а не скрытием кнопок. Опасные действия идут через экран подтверждения с красной кнопкой, каждое действие пишется в журнал.

| Роль | Что может |
| --- | --- |
| `owner` | всё |
| `support` | клиенты (просмотр, заметки, сообщение, блокировка и возврат доступа), обращения, заявки на восстановление. Без тарифов, продления, смены тарифа, бонусов, удаления, возвратов, рассылок, платежей, экспорта, журнала |

Владельцы задаются в `.env` (`ADMIN_IDS`), помощников владелец добавляет и убирает в разделе «Админы», меню команд помощнику ставится автоматически.

| Раздел | Что внутри |
| --- | --- |
| Дашборд | клиенты по тарифам и состояниям, выручка, проданное против ёмкости, ноды, очереди |
| Клиенты | поиск по логину, Telegram id и @username, карточка, продлить на N дней, сменить тариф, бонусные ГБ, заблокировать и вернуть доступ, удалить, написать клиенту, заметка |
| Тарифы | цена в Stars, объём, показать и скрыть. Хранятся в базе и применяются без перезапуска. Смена цены не трогает действующие подписки: клиент продлевает по прежней цене |
| Инвайты | создать N кодов с лимитом использований и сроком, список, отзыв, кто воспользовался |
| Рассылки | сегменты (все, бета, платные, скоро истекают, заблокированные), кнопки-ссылки, отправка сейчас или на время, предпросмотр и пробное сообщение себе, статистика доставки, отмена |
| Ноды | ёмкость, коэффициент продажи, проданное, статус, режим обслуживания с уведомлением клиентов ноды, добавление ноды |
| Техработы | общий режим: над каждым ответом бота у клиентов плашка, в начале и в конце всем уходит сообщение. Админы плашку не видят |
| Поддержка | обращения клиентов из `/support`, очередь, ответ из бота, закрытие, повторное открытие |
| Восстановление | очередь заявок из `/restore`, решение «выполнено» или «отклонить» с комментарием клиенту |
| Платежи | история, поиск по логину, id, @username и номеру платежа Telegram, возврат Stars |
| Админы | помощники |
| Журнал | кто, что и над чем сделал. Тексты сообщений в журнал не пишутся |
| Экспорт | CSV клиентов и платежей, копия базы (`/backup_db`) |

Подробности, которые легко упустить:

- **Рассылки** отправляются со скоростью около 20 сообщений в секунду (лимит Telegram около 30). Получатели записываются в момент начала отправки, поэтому рассылка, прерванная перезапуском бота, продолжается с того же места и никому не уходит дважды. «Заблокировали бота» и «не доставлено» считаются отдельно.
- **Возврат Stars** вызывает `refundStarPayment`. Экран спрашивает, что делать с доступом: «Вернуть и отключить доступ» (отключает автопродление и приостанавливает клиента) или «Вернуть, доступ оставить». Если платёж не последний у клиента, доступ не трогается. Если Telegram отказал, в боте ничего не меняется.
- **Экспорт и копия базы** отправляются только владельцу и только в его личный чат. В CSV нет SSH-ключей и заметок, ячейки, похожие на формулы, экранируются. Копия базы делается через `VACUUM INTO`, содержит всё и должна храниться как секрет. Файлы больше 50 МБ Telegram не примет, для них есть `deploy/backup-db.sh`.
- **Миграции схемы** лежат в `src/plugbackup_bot/db/migrations`, применяются при старте и идут только вперёд.

## Резервная копия базы

В базе лежат Telegram id клиентов, их логины и история платежей. Потеря базы означает потерю привязки клиентов к хранилищам.

Быстрая копия из Telegram: владельцу команда `/backup_db` присылает файл в личный чат.

Разовая копия на сервере, безопасная при работающем боте:

```bash
sudo -u plugbackup-bot sqlite3 /var/lib/plugbackup-bot/bot.db ".backup '/var/lib/plugbackup-bot/backups/bot-$(date +%F).db'"
```

Ежедневно и с проверкой целостности — скрипт и таймер:

```bash
install -m 0644 /opt/plugbackup/bot/deploy/plugbackup-bot-backup.{service,timer} /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now plugbackup-bot-backup.timer
```

Копии лежат в `/var/lib/plugbackup-bot/backups`, хранятся 14 дней. Это та же машина: настройте вывоз копий куда-нибудь ещё и шифруйте их. Восстановление: остановить бота, положить копию на место `bot.db`, запустить бота.

## Проверка на тестовом клиенте

Пройдите это один раз до приглашения людей.

1. `--check` проходит, сервис работает, админ получил «Бот запущен».
2. Администратором: `/nodes` показывает ноду, `/invite 1` выдаёт код.
3. Другим аккаунтом: `/start`, «Бета по инвайту», «Я понимаю риски», код, ключ ed25519. Должно прийти сообщение «Доступ готов» с хостом и логином.
4. На ноде: `storectl usage u1001` отвечает двумя числами. С клиента: `sftp -i <ключ> -o IdentitiesOnly=yes u1001@<хост>` пускает, `ls` показывает только `data`.
5. restic: `restic -r sftp:plugbackup:/data/restic init` и небольшая копия. Через час (или после рестарта бота) `/status` показывает занятое место.
6. `/alerts`: включить «Заполнено на 80%», сменить порог, выключить. Включить «Новый IP»: экран объясняет, что бот получает только хеши.
7. Платная подписка. В `/admin` → «Тарифы» временно поставьте цену 1 Star, оформите тариф со второго аккаунта. Убедитесь, что пришёл «Доступ готов», а в карточке клиента и в «Платежах» видна оплата. Отключите продление в `/status` и проверьте сообщение. Верните Stars в «Платежах» (экран возврата), затем верните нормальную цену.
8. `/restore`: заявка приходит в админ-чат, в «Восстановление» её можно принять или отклонить с комментарием, клиент получает ответ.
9. `/client u1001` → «Заблокировать» → попытка входа по SFTP отклоняется → «Вернуть доступ».
10. `/support` с клиентского аккаунта: обращение появляется в админ-чате, ответ из «Поддержки» приходит клиенту, «Закрыть» закрывает.
11. «Рассылки»: сегмент «Бета», текст, «Пробное сообщение мне», затем отправка. В карточке рассылки доставлено совпадает с числом получателей.
12. «Техработы»: включить, с клиентского аккаунта открыть `/start` (плашка сверху, у админа её нет), завершить. Всем уходят сообщения о начале и конце.
13. `/emoji_preview`: пак читается, эмодзи показываются. Если нет Premium, в админ-чат придёт одно сообщение о переходе на обычные эмодзи.
14. `/backup_db` присылает файл в личный чат, команда у помощника отвечает отказом.

Пока не проверено на реальных Stars, и первый платёж надо наблюдать по журналу:

- Не приходит ли `pre_checkout_query` на автопродление. Бот отклоняет повторную оплату нового доступа, и если Telegram вдруг шлёт такой запрос при продлении, продление не пройдёт.
- Принимает ли `editUserStarSubscription` идентификатор платежа первой оплаты. Он хранится в `clients.sub_charge_id`. Если нет, отключение продления из бота и после смены тарифа будет падать с алертом админу.
- Получает ли бот новый `telegram_payment_charge_id` при каждом продлении.

## Обновление

```bash
cd /opt/plugbackup && git pull
/opt/plugbackup/bot/.venv/bin/pip install --upgrade /opt/plugbackup/bot
systemctl restart plugbackup-bot
```

Миграции базы применяются при старте и идут только вперёд. Перед обновлением сделайте копию базы. Бот отказывается запускаться, если схема базы новее кода.

## Как это устроено

Деньги идут по пути: счёт-ссылка (`createInvoiceLink`, подписка на 30 дней в Stars) → `pre_checkout_query` → `successful_payment` → запись в БД в одной транзакции → задача для `storectl` в очереди. Платёж идемпотентен по `telegram_payment_charge_id`. Если `storectl` упал, задача остаётся в очереди и повторяется (1, 2, 5, 15, 30, 60 минут, дальше раз в час), админ получает алерт.

Состояние клиента: `pending` → `active` → `expiring` → `suspended` → `deleted`. Менять его можно только функцией `transition` в `db/clients.py`, она же пишет журнал переходов.

| Слой | Где |
| --- | --- |
| Правила без ввода-вывода: ключи, тарифы, состояния, жизненный цикл, алерты | `src/plugbackup_bot/domain/` |
| SQLite: схема, репозитории | `src/plugbackup_bot/db/` |
| Логика: платежи, выдача доступа, очередь `storectl`, алерты, админка, рассылки, поддержка | `src/plugbackup_bot/services/` |
| `storectl` по SSH, часы | `src/plugbackup_bot/infra/` |
| Telegram: handlers, клавиатуры, админка с ролями | `src/plugbackup_bot/tg/`, `tg/admin/` |
| Оформление: карточки, кнопки, экраны, баннеры, страницы | `src/plugbackup_bot/ui/` |
| Все тексты для клиента и админа, эмодзи | `texts_ru.py`, `emoji.py` |
| Планировщик, сборка, запуск | `scheduler.py`, `runtime.py`, `__main__.py` |

## Разработка

```bash
python -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/pytest                    # бот
.venv/bin/pytest ../node/tests      # storectl
.venv/bin/ruff check . && .venv/bin/ruff format --check .
```

На Windows интерпретатор лежит в `.venv\Scripts\`.

Тесты не ходят в сеть: Telegram подменён, `storectl` замокан, часы управляются из теста. Контракт между ботом и нодой проверяет `tests/test_node_contract.py`.
