Подключение по SFTP

Пошагово для Linux, macOS и Windows: ключ, настройка SSH, restic и вариант с rclone. Команды можно скопировать кнопкой справа.

Что понадобится

Доступ, который выдал бот @PlugBackupBot, логин для SFTP и установленный restic или rclone. Пароль от репозитория придумываете вы и храните его отдельно от копий.

1. Создайте ключ

Доступ идёт по ключу SSH. Создайте пару ключей ed25519. Приватный файл остаётся у вас, публичный (с расширением .pub) отправьте боту.

Linux и macOS 
ssh-keygen -t ed25519 -f ~/.ssh/plugbackup_ed25519 -C plugbackup
Windows, PowerShell (OpenSSH уже есть в Windows 10 и 11) 
ssh-keygen -t ed25519 -f $HOME\.ssh\plugbackup_ed25519 -C plugbackup

Пароль на ключ можно задать: если приватный файл попадёт к посторонним, без пароля им не воспользоваться. Минус в том, что ssh будет его спрашивать при каждом подключении.

2. Настройте ~/.ssh/config

Файл настроек ssh создаёт один раз. Имя plugbackup в нём станет коротким именем хоста для restic и rclone. Адрес сервера: node1.plugbackup.site. В поле User укажите логин для SFTP.

~/.ssh/config (на Windows: C:\Users\имя\.ssh\config) 
Host plugbackup
    HostName node1.plugbackup.site
    User <логин>
    IdentityFile ~/.ssh/plugbackup_ed25519
    IdentitiesOnly yes

Проверьте подключение командой sftp plugbackup. Если ssh спросит про отпечаток ключа сервера, сверьтесь с отпечатком, который вы получили при подключении. Если позже ssh напишет, что ключ сервера изменился, не продолжайте, пока не выясните причину.

3. Restic

Установите restic из пакетного менеджера вашей системы или с restic.net. Путь к репозиторию: sftp:<хост>:/data/restic, где <хост> — имя из файла config, в примере plugbackup.

Создать репозиторий (один раз)

Linux и macOS 
restic -r sftp:plugbackup:/data/restic init

Restic спросит пароль от репозитория. Он нужен для любой работы с копиями. Если его потерять, данные не восстановить, и у нас их тоже нет.

Сделать копию

Linux и macOS 
restic -r sftp:plugbackup:/data/restic backup ~/Documents

Оставить нужные копии и удалить лишние

Linux и macOS 
restic -r sftp:plugbackup:/data/restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6 --prune

forget отмечает старые снимки, а --prune освобождает место от данных, которые больше никому не нужны. Значения --keep-* здесь примерные, выберите свои.

Windows, PowerShell

PowerShell 
$env:RESTIC_REPOSITORY = "sftp:plugbackup:/data/restic"
restic init
restic backup "$HOME\Documents"
restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6 --prune

Переменная RESTIC_REPOSITORY избавляет от флага -r в каждой команде. Пароль лучше не записывать в открытом виде в скрипты.

4. Вариант с rclone

Создайте remote, который ходит по SFTP. Пароль и ключ останутся в настройках rclone.

Linux, macOS и Windows 
rclone config create plugbackup sftp host node1.plugbackup.site user <логин> key_file ~/.ssh/plugbackup_ed25519
rclone copy ~/Documents plugbackup:/data/rclone

Rclone не шифрует сам по себе

Без шифрования файлы уйдут на сервер в открытом виде. Чтобы данные шифровались на вашем устройстве, создайте поверх SFTP remote типа crypt и храните его пароль отдельно. Порядок настройки описан в документации rclone.

Если что-то не работает

  • Permission denied (publickey). Проверьте, что бот получил публичный ключ, что в config указан приватный файл из той же пары и что логин совпадает с выданным.
  • Host key verification failed. Ключ сервера изменился. Не продолжайте, пока не выясните причину: проверьте статус и напишите в бот.
  • Wrong password. Пароль репозитория неверный. Если вы его потеряли, восстановить данные нельзя.
  • Соединение не открывается. Возможны простои в бете. Проверьте статус работы.
